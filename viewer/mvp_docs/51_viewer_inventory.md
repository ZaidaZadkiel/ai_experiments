# 51. The Inventory

**Decided, not built yet** (`97_second_implementation.md`, `M2Q-21`, answered 2026-11-10). The Inventory is a tab of the Viewer for examining by hand the model the Graph renders. It follows from MVP 2's expanded scope: the graph alone is not enough to understand the examined code (`MVP_scope.md`, section 1.2; `M2Q-22`). This file holds its design: what is decided (section 2), what is open (section 3, none now), and what the docs and checks owe before it is built (section 4). Items are `INV-` and keep their numbers. A decided item says so after its title ("**Title**: decided."), the form the open-questions tracker reads; an open item, once answered, is rewritten the same way and moved to section 2.

**Words used here.** **The Inventory** is the tab and its list of everything the Viewer can see; **the Graph** is the drawn visualization; **[Show in graph]** is the widget through which the Inventory acts on the Graph. **The page's model layer** is the one place in the page that holds the current view and the choices of what the Graph shows (`INV-9`).

## 1. Where it fits

- The page derives nothing: what the Inventory, the Graph and the breadcrumb show is stated by the backend in the model, and the page's model layer only selects from it (`INV-8`, `INV-9`).
- Backend items it rests on: the file index, with each node's relations both ways (`55_viewer_backend.md`, `BE-110`).
- Page items it rests on: the breadcrumb (`50_viewer_ui.md`, `UI-82`), the top view and its folders (`UI-47`), the drawer's tabs (`UI-51`).
- Related questions: what examining a codebase requires (`M2Q-22`), crowded views (`M2Q-6`), whether Details is adequate for examining (`M2Q-25`), kind frames in the Graph, drawing only (`M2Q-26`), a range per declaration (`M2Q-2`), files in their folders (`M2Q-1`, answered for now: examined here first).
- It brings part of navigation (`viewer.md`, `VW-41`, deferred) into MVP 2; its search is its own, not `VW-41`'s.

## 2. Decided

All decided by the user on 2026-11-10, some as suggestions accepted. None is built.

- **INV-1** **Purpose**: decided. To examine by hand **the model the Graph can render**, and **the model data the Viewer knows**, including what it never renders. The Graph is for seeing what is in the view; the Inventory is for checking what exists, and for navigating.
- **INV-2** **Name and place**: decided. A new tab of the drawer, **Inventory**, **between Tools and Problems**: the tabs read Details, Tools, Inventory, Problems, Legend (`UI-51`).
- **INV-3** **Layout**: decided. **The search controls at the top**, **the tree** under them, and **a small content area at the bottom** for the selected row. The content area shows **less than Details** and holds **[Show in graph]**. It is where a row's data is read, since Details doesn't follow the Inventory (`INV-13`).
- **INV-4** **Three sections**: decided. Each collapsed by default:
  - **Files:** the file index (`BE-110`): folders, files and the symbols in each, with their short marks and their unused keys marked. The index is not shown again on its own: this section is the index.
  - **Views:** what the Viewer computes, view by view: each view's nodes, stubs and edges, each edge with the relations it stands for, each view with [Show in graph]. Marked as **computed by the Viewer**, so it is never taken for something in the code.
  - **Model:** the rest of the model, as a raw tree: `run`, `checks`, `formatVersion`, and what `INV-30` brings in.
- **INV-5** **What the Files section holds**: decided. Every file, every folder and every node the Graph can represent, each marked in a short way (`INV-32`). The source's root at the top, folders and files nested by path, and in each file the symbols declared in it, nested by `container` (for example `<root>` › `src/` › `counter.ts` › `total`, `ƒ add`). The tree holds folders, files, symbols and views only; relations are listed in the content area (`INV-14`). The folder structure is examined here for now; the Graph draws no folder frames (`M2Q-1`, `UI-47`).
- **INV-6** **Which JSON**: decided. **Only what the backend produces**, the graph model (`55_viewer_backend.md`, section 6). The Runner's cache is not shown, for now.
- **INV-7** **What "unused" means**: decided. **Whatever is in the model's JSON but not represented in the Graph**, including keys and data added in the future. A key shown only in Details (`VIEW-15`) is unused, since Details is not the Graph. Unused is marked on **the tools' data only**: what the Viewer computes either feeds the Graph or exists for the page, and is marked by its visibility instead (`INV-9`).
- **INV-8** **The model alone says what the Graph represents**: decided. What the page works out today while drawing moves into the model, built by the backend: the "Not connected" entries (`UI-47`), the members written into a node's label (`FND-69`, `FND-102`), the built-in groups (`FND-100`), the facts read by name for the frame's notes, the status icons and the labels (`UI-37`, `UI-48`, `UI-47b`), and each view's path and views one level inside (`UI-82`). The page draws from the model and derives nothing, as with the file index (`BE-110`). Stated in `55_viewer_backend.md`, `BE-114`.
- **INV-9** **The model keeps its own visibility current**: decided. The model is responsible for knowing what it sends to the Graph to render, and for updating that when the view changes, so its visibility information is always current; the Inventory shows it and doesn't work it out.
  - **Where it lives.** The backend builds the model once per run, and moving between views needs no request (`BE-54`), so the work is split: **the backend states, in the model, how every item is rendered in every view** (a node, a member in a label, a stub, an edge's member, or not in that view); **the page's model layer** holds the current view and the choices of what the Graph shows (`INV-18`), updates the visibility whenever either changes, and is **the only thing the drawing code and the Inventory read**. It selects; it derives nothing.
  - **The states.** **Rendered** (sent as a node, a label row, a stub or an edge's member); **not rendered** (in another view, hidden by a choice, a key not drawn); **for reference** (`run`, `checks`, keys shown only in Details, the records of `INV-30`).
  - **"Sent" means sent to render.** The visibility records what the model sends to the Graph's renderer, and that is enough. It is not checked against what the renderer draws: the renderer may leave something undrawn for reasons of its own (for example collapsible nodes in the future, or reasons not known yet), and that is the renderer's concern.
- **INV-10** **The Graph, the breadcrumb and the Inventory move in lockstep**: decided. One state, the current view and the choices of `INV-18`, held by the page's model layer. Every action that moves anything goes through it: a double-click in the Graph, a breadcrumb item, [Show in graph], a choice. On a change the layer makes **one snapshot** from what the backend stated (what is sent to render, the view's path, the views one level inside, which views are reachable), and the three parts read it; none works anything out, so they can't disagree. The Inventory's tree is built once per model; a view change only updates its marks.
- **INV-11** **Every view, and the views with no path**: decided. The Inventory lists every view the model holds, each marked **reachable** or **no direct path**. The backend works out reachability from the top view (a view is reachable when its node is drawn as an enterable node in a reachable view); the layer adjusts it for the choices of `INV-18`, since hiding a node takes its views out of reach. The Inventory is then the way into a view the Graph can't reach.
- **INV-12** **The Inventory follows the Graph by its marks only**: decided. When the view changes, the Inventory shows **"you're here"** on the current view and updates its marks; it never expands, collapses or scrolls by itself. The person opens and closes its rows, so they can go on examining without reopening anything after the view changed.
- **INV-13** **Each part keeps its own selection**: decided. Selecting a row in the Inventory changes neither the Graph's selection nor Details. Only the view and the choices of `INV-18` are shared; [Show in graph] is the one explicit action that acts on the Graph (`INV-15`).
- **INV-14** **Relations are listed in the content area, not in the tree**: decided. Selecting a row lists **that item's relations**, as the Graph highlights the arrows of a clicked node, but as the relations themselves, not merged and not limited to the view:
  - **Uses** and **Used by**, apart: what the item uses, and what uses it; each relation with its kind, its other end and its file and line; built-ins and unresolved names under Uses, with their reason;
  - each relation's **visibility**: drawn in the current view, as part of which edge, or not in this view;
  - **[Show in graph]** on each relation (`INV-15`);
  - **an edge row** in the Views section lists, the same way, the relations it stands for;
  - **its own relations by default**, with **"including members (N)"** to widen the list to its members' relations, grouped by member;
  - **each list collapsed to its count**, opened by a click, scrolling inside the content area; grouping by kind (calls, types, reads) can come later;
  - read from the model's index of each node's relations, both ways (`BE-110`), so the page scans nothing.
- **INV-15** **[Show in graph] acts as if the person had navigated and clicked in the Graph by hand**: decided. Built (`FND-120`); no key yet (`INV-42` (g)). The selection it makes keeps the drawer's tab, so the Inventory stays open; Details follows it all the same. **A glow marks what it lands on** (asked by the user, 2026-11-10): a blue glow around the node or edge, the frame's title for a view, fading out in about 1.2 s; it may play off screen; a new press restarts it; skipped when the system asks for reduced motion (`FND-121`). It sits in the content area, for the selected row, and on each relation listed there. It is the one action of the Inventory that acts on the Graph; it moves the view through the page's model layer, so the Graph, the breadcrumb and "you're here" follow in lockstep. Every [Show in graph] leads to a view: a variable leads to the view that holds it, never to a view of its own.
  - **A node in the current view:** the Graph's selection is replaced by that node, as a plain click would; a selection of several items (`UI-56`) is dropped.
  - **A node outside the current view:** the Graph moves to **the view where the node is drawn as a node** and selects it there. For a variable inside a scope, that is the scope's view; for a node with a view of its own, such as a class, the view that holds it, the class selected, and a double-click then enters it as usual.
  - **Details follows the Graph's selection** (`UI-50`), as after any click: the Graph acts, not the Inventory.
  - **A node drawn only as a member row in another node's label** (`FND-69`): the node whose label holds it is selected, as a click would; Details' Contains list names the member.
  - **A view row** in the Views section: that view is shown, nothing selected, as entering it does.
  - **A relation:** the edge that stands for it in the view where it is drawn is selected, a lifted, merged edge if need be, as clicking that edge would.
  - **A node in no reachable view, or hidden by a choice:** no click could reach it, so the button is disabled and says why.
- **INV-16** **Buttons**: decided. **[expand selected]** and **[collapse all]** (refined by the user, 2026-11-10: one button in place of expand all and recursive expand).
  - **[expand selected]** expands the selected row and everything under it, at every depth. It is **disabled when no row is selected**. **On the topmost row it expands everything.**
  - **[collapse all]** collapses every row.
  - **The topmost row is a single root row, the source's name, holding the three sections** (`INV-4`) (suggestion accepted by the user, 2026-11-10), so [expand selected] on it opens Files, Views and Model alike.
- **INV-17** **Search**: decided.
  - **Controls, at the top of the tab:** a search field; a count, "_N matches_" ("_1 match_"; shortened by the user, 2026-11-10, so the controls stay on one line); a **[regex]** toggle; **[next]** and **[previous]**.
  - **What it matches:** nodes only, by name and ID (`INV-35`); case ignored; [regex] off by default; matches inside collapsed rows counted; [next] and [previous] wrap around at the ends.
  - **Only what the tree lists, and it jumps.** It matches the tree's rows only, never the relations listed in the content area. It keeps its own list of matches, inside the Inventory. [next] and [previous] move along that list: each **selects the match in the tree as if it had been clicked**, expands the rows above it, **scrolls to it**, and shows its content in the content area. It is the Inventory's own selection, so the Graph and Details don't change.
  - **The tree's own search**, not `VW-41`'s search of the project, which stays deferred.
  - **Searching never changes the Graph by itself.** A search, a match or a click on a row leaves the Graph as it is; the Graph changes only through [Show in graph].
- **INV-18** **It changes what the Graph shows**: decided. From the Inventory, a person chooses what the Graph draws; how, in `INV-33`.
  - **Edges that stand for hidden things** (decided by the user, 2026-11-10). The backend lifts and merges each view's edges ahead of time (`BE-53`), and the page derives nothing (`INV-8`), so hiding redoes no lifting: **a hidden node is not drawn, and the edges touching it are not drawn; every other edge is drawn as the backend stated it, its count included, even when some of the relations it stands for start or end in something hidden.** **The edge's label stays unchanged.** **Its hover box** (`50_viewer_ui.md`, `UI-86`) **says how many of its relations are hidden**: "3 relations (1 hidden)". A relation is hidden when either of its ends, or a container of either end, is hidden; the page's model layer finds this from the model's index of each node's relations (`BE-110`), as it selects, without lifting anything.
- **INV-30** **Records dropped before the model**: decided (suggestion accepted by the user, 2026-11-10). A group the Viewer doesn't know, and an invalid record, are dropped before the model and only named in `checks` (`BE-51`, `BE-52`). **The model keeps them in a section of their own, marked unused**, so the Inventory's Model section shows them and future extra data can be seen. Stated in `55_viewer_backend.md`, `BE-113`.
- **INV-32** **The short marks on a row**: decided (suggestion accepted by the user, 2026-11-10). The kind as a glyph or word (`ƒ`, `class`, `type`), then the label; status icons on files and folders (`UI-48`); `exp` when exported; a visibility mark: ● rendered in this view, ○ not in this view, ⊘ hidden by a choice, ▫ for reference; ▸view when it has a view; ⌖ for "you're here", **at the tree's left edge**, in a column of its own pinned there, on the current view's rows (asked by the user, 2026-11-10); in the Views section, *reachable* or *no direct path* (`INV-11`). Every mark a shape or text, never color alone (`UI-40`). **The visibility mark comes last on every row**, so the circles line up at the right edge (asked by the user, 2026-11-10); **the Legend lists every mark** (`UI-87`).
- **INV-34** **Order of rows**: decided (suggestion accepted by the user, 2026-11-10). Files: folders first, then files, by name; folders skipped as a whole (`RUN-34b`) with their file count, not expandable; symbols in source order. Views: the top view, then each view under its parent, in the same order. Model: the JSON's own order.
- **INV-37** **What the content area shows**: decided (suggestion accepted by the user, 2026-11-10). A header with the kind and label; the ID, copyable; the file and line; its visibility in the current view and whether it has a view; its unused keys; then the relation lists, collapsed to their counts (`INV-14`), and [Show in graph] (`INV-15`). The rest stays in Details, reached through [Show in graph].
- **INV-38** **Where the buttons sit**: decided (suggestion accepted by the user, 2026-11-10). In a row under the search controls: [expand selected], [collapse all] (`INV-16`).
- **INV-33** **Choosing what the Graph shows**: decided (suggestion accepted by the user, 2026-11-10). Built (`FND-120`): the kind toggles cover the code's kinds, not files and folders (hiding every file would empty the Graph) and not built-ins (they are not nodes); hiding a folder hides the files in it; when the view shown becomes hidden, the Graph shows the nearest view above it that is still shown. **A hide keeps the layout** (asked by the user, 2026-11-10): the nodes that stay don't move and the zoom stays; **the layout runs again only on a show** that gives the view shown a node back, or when the view shown changes (`FND-121`). How `INV-18` works; how edges standing for hidden things are drawn is decided there.
  - **Per kind and per node.** **A toggle per kind**, with **[show all]** to reset; **a checkbox per node** at the start of its row in the Files section.
  - **Where the toggles sit** (changed by the user, 2026-11-10): **a bar at the bottom of the pane**, "Show: all ▴" or "Show: 2 kinds hidden ▴", **opening a panel upward over the content area**, like the activity line; closed by its bar, a press outside it or Esc. In the panel, **the toggles are equal buttons in a grid**, three across, then [show all]. **[Recalc]**, in the grid's last cell (asked by the user, 2026-11-10), lays the view out again from the start and fits it, what is hidden left out: it closes the gaps a hide leaves and undoes any dragging; what is hidden and selected stays. **Their order is fixed, the least likely to be hidden first and the most likely last**: namespaces, classes, interfaces, type aliases, enums, functions, methods, constructors, accessors, properties, enum members, imports, parameters, variables; every known kind always there, one the source doesn't have disabled, a kind not known here after them. (They first sat in a row under the buttons, which took four lines in a 380 px drawer.)
  - **Hiding a node hides everything inside it**; its views become *no direct path* (`INV-11`) and its [Show in graph] is disabled, saying why (`INV-15`). A hidden item is marked ⊘, *hidden by a choice* (`INV-32`).
  - **A tick takes effect at once**, since ticking is itself the manual request; the Graph, the breadcrumb and "you're here" follow in lockstep (`INV-10`). The hidden set is part of the shared state, beside the current view; the page's model layer uses it when it selects what is sent to render, and redoes no lifting.
  - **For the page only**, not saved, for now.
  - **The per-kind toggles are `M2Q-6`'s filters**, built once (types, built-ins, parameters, and every other kind).
- **INV-35** **What search matches**: decided (by the user, 2026-11-10). **The minimal implementation: nodes only, by name and ID.** Rows of the Files section that are nodes (folders, files, symbols) match on their name or their ID; a file's or folder's path is its ID. Views, the Model section, kinds, and the JSON's keys and values are not searched. **To be widened once it has been tried in practice**: the user expects search may need **a view of its own**, how not yet decided (related: `viewer.md`, `VW-41`, deferred).
- **INV-31** **How an unused part is marked**: decided (suggestion accepted by the user, 2026-11-10). A muted row with the word "unused", not color alone (`UI-40`).
- **INV-36** **One selected row**: decided (suggestion accepted by the user, 2026-11-10). The tree has a single selection only, as search's jumping (`INV-17`) and the content area (`INV-37`) both assume one selected row; [expand selected] acts on that row (`INV-16`).
- **INV-39** **Size on real code**: decided (suggestion accepted by the user, 2026-11-10). Smaller since relations are not rows (`INV-14`); on `app/`, hundreds of rows. Rows are built only when first opened; [expand selected] asks first when it would open more than 2,000 rows, giving the count, as it can on the topmost row.
- **INV-40** **A new run or another source**: decided (suggestion accepted by the user, 2026-11-10). When the model is replaced and the tree rebuilt: on a new run of the same source, the open rows, the selection and the search are kept, matched by ID, and the search runs again on the new model; rows whose ID is gone are dropped, and the count shows the change. On another source, everything is reset, since IDs don't carry over between sources.
- **INV-41** **Keyboard navigation**: decided (by the user, 2026-11-10). Built (`UI-87`), with `INV-42` (a): ↑ and ↓ move the keyboard's focus only, shown by an outline; a click moves it too. The keys act only where the focus is, so they never reach the Graph.
  - **In the tree:**
    - **Enter:** on a row with nothing inside it, shows its content in the content area (`INV-37`); on a row with something inside, opens it.
    - **→:** opens the row; on a row already open, moves to its first sub-item; on a row with no sub-items, does nothing.
    - **←:** on an open row, closes it; on a closed row, moves to its parent. One step per press: moving to the parent and closing it takes two presses.
    - **Esc:** clears the selection and moves the focus to the search field.
  - **Anywhere else in the pane** (the content area, a selected text, the copy button, the relation lists, the buttons), **Esc moves the focus to the search field**, the selection kept (asked by the user, 2026-11-10). Built: the pane remembers whether the last press was in it, as selected text has no focus; Esc after a click elsewhere, such as on the Graph, is left alone.
  - **In the search field:** **Enter** does what [next] does (`INV-17`).
- **INV-43** **The search's overview strip**: decided (by the user, 2026-11-10, option B of two). Built (`UI-87`). A thin strip just right of the tree, as tall as it, with **a small yellow square for each match**, placed **where its row sits among the rows shown**, as a scrollbar would place it; a match inside a closed row is placed at its nearest shown parent, so squares move as rows open and close. **The current match** ([next], [prev]) is drawn darker and outlined. Squares closer than 2 px merge into one. **Only an indication:** it takes no clicks and moves nothing in the layout; it is empty with no search or no match. (Option A, a place among all the Files rows, open or closed, was not chosen.)

## 3. Open

- **INV-42** **The keys `INV-41` leaves open.**
  - (a) Answered (by the user, 2026-11-10): **↑ and ↓ only move** to the row above or below among the rows shown; they show no content and open nothing. A row opens only with → or Enter.
  - (b) **Enter on a row already open:** nothing, or close it (`INV-41` gives closing to ←).
  - (c) **Shift+Enter in the search field:** as [prev], as built today, or nothing.
  - (d) **Esc in the search field:** clear the search, or nothing.
  - (e) **↓ in the search field:** move the focus into the tree, on the selected row or the first one.
  - (f) **Home and End:** the first and last row shown.
  - (g) **A key for [Show in graph]** (`INV-15`, the second pass), for example **G**, kept off Enter since it is the one action that changes the Graph.
  - (h) **The focused row:** shown by an outline, not by color alone (`UI-40`); clicking a row gives the tree the focus.

  *Suggested, not accepted:* (b) nothing; (c) as [prev]; (d) clear the search; (e) yes, on the selected row, else the first; (f) yes; (g) **G**; (h) yes.

New points take the next free number from `INV-44`.

3. **The backend's model format 3** (`FND-115`), checked by `tests/viewer/check-server.mjs` against the expected model.

5. **The tab** (`UI-87`, `UI-51` with five tabs): read-only (`FND-117`), keyboard (`FND-119`), hiding and [Show in graph] (`FND-120`, `FND-121`, `FND-122`), refined in use (`FND-123`). Checked by `tests/viewer/browse/inventory.json` and `inventory-hiding.json`.
