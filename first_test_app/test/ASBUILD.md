## What the app does, according to the code

The app is a small Node.js HTTP server (`src/server.js:11-33`) that keeps a list of names and how many times each one has been "considered". It stores them in a SQLite file at `data/app.db` (`src/db/init.js:8`), in one table, `names` (`data/init.sql:4-11`).

`npm start` runs `src/index.js:3`, which opens the database and listens on `PORT` (default 3000). If `data/app.db` is missing, it crashes on purpose (`src/db.js:9`). `npm run db:init` creates the database from `data/init.sql` (`src/db/init.js:16-33`).

Every request goes through one handler (`src/app.js:89-104`):

| Request                           | What the code does                                                                                     | Code                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------- |
| Any method other than `GET`       | `303` redirect to `/`                                                                                  | `src/app.js:90`, `:13-16`                 |
| `GET /`                           | Page with a table of every name and its count, most considered first                                   | `src/app.js:35-52`, `src/db.js:22-24`     |
| `GET /greet` with no `name`       | Welcome page with a form that submits to `/consider`                                                   | `src/app.js:67`, `:54-56`                 |
| `GET /greet?name=X`               | Saves the normalized name (new record with count 1, or updates `last_time_seen`) and shows "Hello, X!" | `src/app.js:66-73`, `src/db.js:14-17`     |
| `GET /consider` with no `name`    | Form page                                                                                              | `src/app.js:76`, `:58-64`                 |
| `GET /consider?name=X`, X known   | Adds 1 to the count, updates `last_time_seen`, shows "you have considered X"                           | `src/app.js:79`, `:86`, `src/db.js:19-21` |
| `GET /consider?name=X`, X unknown | "I dont know X, but if you want i can greet them", with a link to `/greet?name=X`                      | `src/app.js:79-85`                        |
| Any other path                    | `303` redirect to `/`                                                                                  | `src/app.js:101-102`                      |

Names pass through one function, `normalizeName` (`src/name-rule.js:29-38`), before they touch the database:

- spaces at both ends are trimmed
- at most 50 characters are kept
- `< > & " '` become HTML entities
- `? # % + / =` and anything outside printable ASCII become `_`

Matching ignores case for A to Z (`data/init.sql:6`). Pages show the name exactly as typed, HTML-escaped (`src/app.js:72`, `:82`, `:86`), while the table shows the saved form (`src/app.js:45`).

All HTML lives in 9 templates in `src/views/`. They're read from disk on every request (`src/templates.js:20-22`) and filled by replacing a fixed list of 7 `{{__PLACEHOLDER__}}` strings in one pass (`src/templates.js:7-17`, `:30-37`). The welcome and form pages include a browser copy of the name rule (`src/views/name-rule.html:4-32`). As you type, it shows what will be saved, and it never blocks submitting.

There is no error handling. Any failure during a request rejects the handler's promise and crashes the process (`src/app.js:18-21`).
